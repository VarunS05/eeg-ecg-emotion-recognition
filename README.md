# EEG/ECG Emotion Recognition (DREAMER)

Predicts self-reported valence/arousal/dominance from EEG and ECG signals, using the [DREAMER dataset](https://ieeexplore.ieee.org/document/7887697) (Katsigiannis & Ramzan, 2018) — a published, peer-reviewed benchmark of 23 subjects watching 18 film clips while wearing a 14-channel EEG headset and 2-lead ECG, rating their valence/arousal/dominance (1–5) after each clip.

## Why this exists

Earlier versions of this project trained a model on the same kind of EEG/ECG band-power features but with labels generated by a hand-written threshold rule applied to those same features — which reports a misleadingly high accuracy (~95%) because the model is partly just reconstructing the labeling rule, not predicting real emotion. This version uses DREAMER's actual self-reported valence/arousal/dominance scores as ground truth instead, and evaluates with subject-independent cross-validation so no person's data leaks between train and test.

## Method

1. **EEG features**: for each of 14 channels, band power (theta 4–8Hz, alpha 8–13Hz, beta 13–30Hz, gamma 30–45Hz) via Welch PSD, baseline-corrected by subtracting each subject's resting-state band power for that channel — this removes per-subject EEG offset rather than comparing raw power across people.
2. **ECG features**: R-peak detection → mean heart rate, SDNN, RMSSD, and LF/HF power ratio of the RR-interval tachogram (standard heart-rate-variability features).
3. **Labels**: valence/arousal/dominance scores are binarized at the standard DREAMER threshold (`> 3` = high, `<= 3` = low).
4. **Evaluation**: Random Forest classifier, 5-fold **GroupKFold by subject** — every fold tests on subjects entirely unseen in training, which is a much harder and more honest setup than a random split (EEG signals vary a lot between people; a random split lets the model partly just memorize per-subject patterns).

## Results

```
python train.py
```

```
Subject-independent 5-fold cross-validation (GroupKFold by subject):
  valence   : accuracy=0.578 (+/-0.080)  macro-F1=0.525  majority-class baseline=0.605
  arousal   : accuracy=0.518 (+/-0.055)  macro-F1=0.476  majority-class baseline=0.561
  dominance : accuracy=0.593 (+/-0.036)  macro-F1=0.585  majority-class baseline=0.522
```

Only **dominance** clearly beats the majority-class baseline. This is consistent with the literature — DREAMER's own authors report ~62% baseline accuracy for these tasks, and subject-independent evaluation (used here) is known to be substantially harder than subject-dependent/mixed evaluation, since EEG patterns vary a lot between individuals. Reporting the majority-class baseline alongside the model's accuracy is deliberate: it makes clear when a headline accuracy number isn't actually better than always guessing the more common class (as is the case here for valence and arousal).

## Setup

DREAMER.mat is not included in this repo (452MB, and requires requesting access from the original authors — see the [dataset page](https://ieeexplore.ieee.org/document/7887697)). A pre-extracted feature table (`data/dreamer_features.csv`, statistics only, no raw signal data) is included so `train.py` runs immediately without the original file.

```bash
pip install -r requirements.txt
python train.py                                    # uses the cached feature table
python train.py --dreamer-mat data/DREAMER.mat --rebuild   # re-extract from the raw dataset
```

```
train.py        # CLI: extract features (or load cache), evaluate with subject-independent CV
data/

```

## Limitations

- Random Forest on hand-crafted band-power/HRV features, not a learned representation (e.g. a CNN over raw signal) — chosen for interpretability and to keep the feature/label relationship auditable, at some cost to potential accuracy.
- LF/HF ratio has coarse frequency resolution given the ~200-second clip length; treat it as a rough HRV indicator, not a precise clinical measure.
- Single ECG lead used per trial; the second lead is unused.
- Binary high/low framing collapses the original 1–5 scale; a regression or ordinal setup would preserve more information.
